2. Executive Summary & Problem Statement
Despite an industry-wide decline in bulk fraud volumes, Nigeria’s banking sector suffered massive high-value losses due to highly targeted operations. The core issue is the 
speed of settlement
; the NIBSS Instant Payment (NIP) protocol moves money within seconds, leaving traditional batch-processed fraud detection completely useless.
Local Threat Landscape Addressed:
Account Takeover (ATO) via SIM-Swap:
 Criminals clone SIM cards to intercept OTPs. 
Sleeper/Mule Accounts:
 Accounts opened via compromised or "farmed" KYC (BVN/NIN) that stay dormant for months before suddenly routing millions of Naira. 
Social Engineering / "Mushing":
 Victims are manipulated into transferring funds voluntarily via USSD or Mobile Apps.
Generative AI Deepfakes:
 Bypassing standard video-selfie liveness checks during remote digital onboarding.

4. Functional Requirements
4.1 Onboarding & Device Binding (CBN 2026 Compliance)
FR-1.1: Mandatory Device Binding:
 The mobile app must restrict concurrent usage to a single unique device GUID. Any device change must automatically drop the application into an "Unauthenticated State." 
FR-1.2: The 24-Hour Cooling Velocity Cap:
 Upon activation of an account on a 
new device
, the system must automatically enforce a strict inbound and outbound transactional cap of 
₦20,000 for the first 24 hours
. 
FR-1.3: Active Liveness Checks:
 The onboarding process must reject flat media (photos, 
prerecorded
 videos) by using active challenge-response liveness tracking (e.g., specific random eye movements or randomized text phrases) to prevent generative AI deepfake spoofs. 
4.2 Real-time Transaction Evaluation
FR-2.1: In-Stream Risk Evaluation:
 Every single NIP transaction request must be intercepted via an asynchronous message broker (e.g., Apache Kafka) and parsed by the Smart Agents.
FR-2.2: Dormancy Reactivation Guard:
 If an account shifts from a dormant state (no ledger updates for greater than 180 days) to active, any outbound transfer above ₦50,000 must trigger mandatory Multi-Factor Authentication (MFA) along with real-time validation against the centralized NIBSS BVN/NIN watchlists.

NFR-1.1:
 Total pipeline execution latency from transaction API receipt to agent determination must not exceed

NFR-1.2:
 The system must comfortably maintain a throughput of

 (Transactions Per Second) to match payday traffic surges typical in the Nigerian banking sector.
5.2 Security, Compliance & Isolation

 In accordance with the Nigeria Data Protection Act (NDPA), all PII (Personally Identifiable Information) including plain-text

, phone numbers, and facial vectors must be obfuscated via AES-256-GCM encryption before parsing or logging.
NFR-2.2 Model

 The system must output a specific, human-readable reason code string for every rule override or machine learning flag (e.g.,

The Ingestion Tier:
 The API Gateway acts as a non-blocking reverse proxy. It passes the core payload to the 
Fraud Orchestrator
 via Internal

 while dumping deep biometric/device metadata into 
Apache Kafka
 for continuous offline pattern learning and graph updates.
Parallel Execution Core:
 The Fraud Orchestrator splits incoming evaluations across the 4 micro-agents using parallel worker routines (Golang channels or Java Virtual Threads). Each micro-agent is allocated a strict 
45ms deadline timeout
. If an agent fails to respond within its window, the engine falls back to fallback heuristics to protect transaction flow.
The State & Cache Tier:
 
Redis Enterprise Cluster
 acts as the high-speed data plane, keeping real-time device-binding maps, rolling 24-hour transaction volume metrics per account, and temporary CBN watchlist flags accessible with sub-millisecond lookups.
